## Claude Notes
- Global rules: `~/.claude/CLAUDE.md`; settings, hooks, and skills live in `~/.claude/settings.json`, `~/.claude/agents/`, and `~/.claude/skills/`. Override with `CLAUDE_AGENTS_PATH` or `CLAUDE_CONFIG_DIR`; on Windows `~` is `%USERPROFILE%`.
- Model ladder: `haiku` = cheap, fast tier for lookup, routing, extraction, and routine checks: `low` for short, simple, high-volume work, and `medium` (its default) once the task must search, follow a long prompt, or verify its work, because at `low` it skips searches, stops early, and skips checks more often; `sonnet` = balanced tier, `medium` for bounded coding and `high` for hard reasoning or long work; `opus` = flagship for hard reasoning, broad refactors, and long-horizon agent work, and the Claude Code default, with `medium` as its default effort; `fable` = apex, only when Opus has measurably fallen short. Haiku 4.5 has no effort control, so do not route to it. Effort is a real lever: `xhigh` and `max` earn their cost only on measured quality gains, and `/effort` saves per model. Effort names vary by model, so verify exact model IDs and aliases before scripting and recalibrate effort after model changes. At `xhigh` and `max` a long deliverable may be drafted in thinking and again in the reply. For safeguard false positives on Fable, try asking "are there bugs" instead of "does this compile" and omit unnecessary base64 from tool output.
- Haiku bills prompts over 100k tokens at a much higher rate and agent loops resend context each turn; keep Haiku workers scoped and short-lived.
- Re-check an earlier answer when later work contradicts it.
- Use the Skill tool for skills selected under the core activation policy.
- `CLAUDE.md` files are hierarchical memory loaded at startup; keep global files concise and put project facts in project `CLAUDE.md` or `.claude/rules/`. A project with only `AGENTS.md` is read as a fallback when no `CLAUDE.md` exists. `"attribution": false` in `settings.json` turns off the built-in commit and PR attribution.
- `--bare` skips hooks, LSP, plugin sync, and skill walks; `--safe-mode` disables all customizations for troubleshooting. Use either only when that reduced startup is intentional.
- Auto mode is the default permission mode: risky actions are classifier-gated, which does not replace the confirmation rules; deny rules are absolute and can match tool parameters. Project-scope `bypassPermissions` is ignored, so set it in user settings or `--permission-mode`; `--restricted` strips shell and network tools for untrusted runs. Subagents and forked side tasks run in the background by default: report them as `[waiting]` and end the turn only when the harness wakes you on completion. `CLAUDE_CODE_SUBAGENT_MODEL` is a default that agent `model:` fields override; the `_FORCE` variant restores the hard override.
- `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` is safer for shared machines but can hide host process and credential detail; persistent plugin state belongs under the tool's plugin data path, not bundled plugin files.
- The `UserPromptSubmit` hook re-injects invariants every turn and survives compaction, but does not fire on subagent dispatch; deliver the subagent block separately.
- Verify after deploy: `/memory` lists the loaded files and the agent list the roles; check the resolved model and provider, because aliases may be overridden and `haiku` and `sonnet` select 5.5 only on the Anthropic API (other providers may resolve older models). The desktop Code tab reads these files; the Chat tab does not.
- Use `AskUserQuestion` when available: 2-4 options, recommended first with "(Recommended)" in its label; previews and multi-select are available. It adds "Other" itself.
