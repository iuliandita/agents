## Codex-Specific Notes
- Generated from this repo's `prompts/core.md` plus `prompts/harnesses/codex.md`. Edit the source fragments, then run `scripts/sync-ai-prompts`.
- Model ladder: fast/affordable tier (GPT-5.6 Luna-class) = lower cost; balanced tier (Terra-class) = routine work; flagship (Sol-class, current Codex CLI default) = hardest reasoning and long-horizon work; GPT-5.4 and 5.4 Mini are retired and auto-migrate to Terra and Luna. Verify exact model IDs and auth-plan availability before scripting; do not freeze stale names in prompts.
- Effort runs `low` through `xhigh`, `max`, and `ultra`; `ultra` adds automatic subagent delegation at several times the token cost, and subagent tokens count toward the root goal budget. Custom roles in `~/.codex/agents/*.toml` apply only when `spawn_agent` passes `agent_type` naming the role, and only `fork_turns="none"` lets the role's own model and effort take effect, so dispatch custom roles with both set and a self-contained task. Prefer explicit effort flags in automation when supported, but verify current CLI/docs first.
- Codex discovers `AGENTS.md` in a stable chain: `$CODEX_HOME/AGENTS.override.md` or `AGENTS.md` (global, default `~/.codex/`), then project root down to CWD, concatenated under a byte cap (`project_doc_max_bytes`, 32 KiB default), so keep the global file lean. Untrusted projects do not contribute project-level `AGENTS.md`, so check trust before assuming repo rules loaded.
- Skills are first-class in current Codex: the catalog is budgeted and selection is routed, so invoke a relevant skill before starting skill-adjacent work rather than improvising.
- Automation: `codex exec` accepts a prompt plus stdin for pipelines. Use explicit flags such as `--json`, `-o`, `--ephemeral`, and `--skip-git-repo-check` when they improve determinism, prefer structured output, and keep prompts self-contained. Approval policy is `on-request` or `never`; `--approve-for-me` routes approvals through automatic Guardian review under `workspace-write`. The `update_plan` tool is off by default, so plan in plain text unless `tools.update_plan.enabled` is set. `codex mcp-server` is deprecated; expose Codex through the app server.
- Long-running work is session-based: `codex agents` lists and controls tasks and `codex queue` sends messages to existing local or remote sessions. Verify subcommands and flags against current CLI help before scripting them.
