## Codex-Specific Notes
- Generated from this repo's `prompts/core.md` plus `prompts/harnesses/codex.md`. Edit the source fragments, then run `scripts/sync-ai-prompts`.
- Model ladder: fast/affordable tier (GPT-5.6 Luna-class) = lower cost; balanced tier (Terra-class) = routine work; flagship (Sol-class) = hard reasoning and long-horizon work; apex (GPT-6 Astra-class) = the hardest end-to-end work across code, apps, and research. Astra rollout and account availability vary, so retain Sol as the fallback. GPT-5.4 and 5.4 Mini are retired and auto-migrate to Terra and Luna. Verify exact model IDs and auth-plan availability before scripting; do not freeze stale names in prompts.
- Astra API reasoning supports `low`, `medium`, `high`, `xhigh`, and `max`; Codex may also expose `ultra`. Verify the selected model and harness's supported settings before scripting; do not assume API and app effort ranges match. When migrating to Astra, preserve effective effort initially (`low` replaces unsupported `none` or `minimal`), then measure lower settings. Keep routine role defaults; evaluate apex for difficult planning and review. Expose only the tools the task needs.
- Codex discovers `AGENTS.md` in a stable chain: `$CODEX_HOME/AGENTS.override.md` or `AGENTS.md` (global, default `~/.codex/`), then project root down to CWD, concatenated under a byte cap (`project_doc_max_bytes`, 32 KiB default), so keep the global file lean. Untrusted projects do not contribute project-level `AGENTS.md`, so check trust before assuming repo rules loaded.
- Skills are first-class in current Codex: the catalog is budgeted and selection is routed, so invoke a relevant skill before starting skill-adjacent work rather than improvising. Custom roles in `~/.codex/agents/*.toml` apply when `spawn_agent` passes the role's `agent_type`; use `fork_turns="none"` and a self-contained task to apply the role's model and effort instead of inheriting the parent. Subagent tokens count toward the root goal budget. Verify current CLI/docs before setting automation flags.
- Automation: `codex exec` accepts a prompt plus stdin for pipelines. Use explicit flags such as `--json`, `-o`, `--ephemeral`, and `--skip-git-repo-check` when they improve determinism, prefer structured output, and keep prompts self-contained. Approval policy is `on-request` or `never`; `--approve-for-me` routes approvals through automatic Guardian review under `workspace-write`. The `update_plan` tool is off by default, so plan in plain text unless `tools.update_plan.enabled` is set. `codex mcp-server` is deprecated; expose Codex through the app server.
- Long-running work is session-based: `codex agents` lists and controls tasks and `codex queue` sends messages to existing local or remote sessions. Verify subcommands and flags against current CLI help before scripting them. Treat mid-task corrections and side questions as steering: incorporate them while preserving the active objective and completed work, unless the user clearly cancels or replaces the task.
