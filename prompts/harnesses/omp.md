## Oh My Pi Notes
- Global rules: `~/.omp/agent/AGENTS.md`; config `~/.omp/agent/config.yml`. `PI_CODING_AGENT_DIR` moves the global rules file (task agents still load from the home path), and a named profile (`--profile`, `OMP_PROFILE`) uses `~/.omp/profiles/<name>/agent` instead. Override the rules path with `OMP_AGENTS_PATH`.
- Project context, highest first: `.omp/AGENTS.md` (nearest ancestor), `.claude/CLAUDE.md`, `.agents/AGENTS.md`, then any `AGENTS.md` or `CLAUDE.md` walked up from CWD. User-level `~/.agents/AGENTS.md` also loads; `~/.claude` sources load only when enabled.
- Non-interactive: `omp -p` with `--mode json` for pipelines. `--no-skills`, `--no-extensions`, and `--no-tools` strip customizations; say so when global rules were intentionally bypassed.
- Model roles live under `modelRoles` in `config.yml` (`default`, `smol`, `slow`, plus task-specific roles such as `task` and `plan`). Tiers render as role aliases (`@smol`, `@default`, `@slow`), so the roles decide the actual models. Thinking levels are `off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, and `auto`; set them per session with `--thinking`.
- Skills load from `~/.omp/agent/skills`, `.omp/skills`, and `~/.agents/skills`; `~/.claude/skills` only when enabled.
- Task agents are markdown in `~/.omp/agent/agents/` (user) and `.omp/agents/` (project), with `name`, `description`, `tools`, `model`, and `thinkingLevel` frontmatter. Project beats user beats bundled; the bundled `scout`, `reviewer`, `security-reviewer`, `task`, and `sonic` stay available unless a file reuses the name, as `reviewer` does here. An agent without the `task` tool cannot spawn others.
- Hooks live in `~/.omp/agent/hooks/pre|post` and extensions in `~/.omp/agent/extensions`; no invariants channel is wired here, so the hard rules ride in the rules file and each rendered agent.
- Verify discovery after deploy: open `/agents` in a session and confirm the six roles and their models, and check the session header for the resolved model and thinking level.
